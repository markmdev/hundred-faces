# 2026-09-18, later: launch corrections

One correction batch on the launch commits, before the production deploy:
what changed, what was kept, the recording it now runs on, and what was
verified.

## What changed

- **After the batch, four more.** The byte limit measures the `m=` query as
  `URLSearchParams` writes it (it escapes `!` and friends that
  `encodeURIComponent` leaves alone), at 13,000; API requests go out with
  `referrerPolicy: "no-referrer"`, since the page URL as a Referer doubled the
  request and tripped the local Node server's 16 KB header limit. The page
  URL now carries the message being judged (set when a request starts, kept
  through a failed judgement so a refresh retries it, dropped on clear or
  refusal), while Copy link and Post on X hand out the shown wall's link,
  built from its message alone. `.share[hidden]` hides the row (its
  `display: flex` had been overriding `hidden`). The privacy line reads
  `Your text goes to Jev and comes back as numbers; it lives in the link and
  nowhere else.`

- **Privacy copy.** The page, the README, and AGENTS.md say `Your text goes
  to Jev and comes back as numbers; it lives in the link and nowhere else.` The README
  says what does see the message: the handler logs status and duration only,
  but the message rides in the URL, so Vercel's request logs (an hour on
  Hobby) and the CDN cache key (a day, plus a week stale) hold it, TypeSafe
  receives it. Web Analytics gets the page URL with `m` removed by a
  `beforeSend` hook in `src/client/main.ts`, Vercel's documented redaction
  path. Observed on the wire after Web Analytics was enabled and a preview
  redeployed: the page-view POST body carried the bare page URL while the
  address bar carried `?m=`; typing a second message sent no further view.
- **One shown wall.** The browser keeps `shown` (text, response, whether it
  came from a recording), set when a response settles and cleared when the
  wall rests; the URL's `m` (`history.replaceState` moved from request start
  to settle), Copy link, Post on X, and the saved image's header all derive
  from it, so a wall pending behind a shown one can no longer put its text on
  the other's faces. A failed or refused message rests the wall and drops
  `m`, as a clear does.
- **Recordings pinned to the preset text, kept as a build input.**
  `test/fixtures/` is `recordings/` (`jev-presets.json`, `schema.ts`), since
  `npm run build` reads it. The hash covers the preset ids and messages;
  `recordedWall` takes the preset and refuses a recording whose message is
  not the code's; `scripts/build-presets.ts` sweeps `public/presets/` of
  preset files it did not just write. Re-recorded once (below).
- **One message limit, counted one way.** `messageTooLong` in
  `src/shared/types.ts`: 2,000 code points, then 13,000 bytes of
  `encodeURIComponent(message)` (Vercel's CDN answers 414 above 14 KB before
  the function runs). The server answers 413 with its reason; the browser
  runs the same check on the typed path and on a `?m=` link before any
  request, rests the wall, and shows the reason. `textarea.maxLength` is gone.
  The contract test covers both bounds on both sides with the same strings
  (2,001 ASCII; 2,000 emoji, which fit the count and not the bytes) and
  drives `api/react.ts`'s fetch export against the recording through
  `mock.module`, so `npm test` passes `--experimental-test-module-mocks`.
- **Saved image.** A word wider than the line (a URL, a hashtag) is broken by
  code point to fit; the ellipsis trim is by code point, so an emoji is never
  split; the header layout numbers are named. The stylesheet is the one owner
  of how a face is stroked and filled: the canvas reads stroke, width, caps,
  joins, and fills from a rendered face's parts with `getComputedStyle`.
- **The person card, named once.** `tooltip.ts` is `card.ts`; `#card`,
  `.card`, `Card`. `role="tooltip"` on a hover device; `role="dialog"` with
  the person's name as `aria-label` and `tabindex="-1"` on touch, so a tap
  inside the sheet keeps it. Focus leaving the wall and the card closes it in
  both modes. The sheet-mode guard that cleared inline `left`/`top` is gone;
  the mode is fixed at load.
- **Presets say so.** A recorded preset's calls stat reads `10 parallel calls
  to jev-1.13.0, recorded`; live walls unchanged.
- **Share line and copy.** `47% annoyed, 86 understand it, 12 trust it` (a
  share of the mean distribution, not a headcount). The intro says `Four
  hundred answers per update`; `og:description` and the meta description
  carry `invented`.
- **Docs and scripts.** The README states what is verified about
  `supportsCancellation` (the browser aborts, the Node adapter forwards it;
  Vercel's side unobserved). `scripts/probe.ts` runs against the six current
  presets in pairs. AGENTS.md names the two build noises. The phone line in
  the entry below now says the faces are 32 px buttons by design.
- **Small code.** `judge()` is `wallFor()`; `server/react.ts` says "react" is
  the reaction; the identity check on `inFlight` has its reason; one 44 px
  touch-target rule under `(pointer: coarse)`, one focus-ring rule,
  `.latency` for the big stat; `batchCount()` in `wall.ts`; `IMAGE_SIZE`
  unexported, `fetchPreset` without `baseUrl`; the Node adapter answers 400
  to a `Host` that makes no URL and drops the socket on a failure after the
  headers are out; `scripts/dev.ts` exits 1 on a signal-killed child and with
  the builder's status when the presets fail; `test/react.test.ts` has one
  owner for the abort flag; `test/presets.test.ts` asserts the whole wall once.

# 2026-09-18: launch shape on Vercel, batch size 10, six presets, share loop

What shipped for the public launch, the decisions behind it, the recording
the suite and the page now run on, and what was verified on the preview.

## What shipped

- **Vercel: static site plus one function.** Vite builds `dist/`; `api/react.ts`
  is the one function. It and the local server (`server/main.ts`, loopback
  only, behind Vite's proxy as before) call the same Web-standard handler,
  `react(request)` in `server/react.ts`. `server/node.ts` adapts Node's
  `IncomingMessage` to a `Request` and a dropped connection to an abort;
  `vercel.json` turns on function cancellation so Vercel does the same. The
  Node server no longer serves static files; `npm start` is gone.
- **Judging is a GET**, `/api/react?m=<message>`, 2,000 code points at most
  (413 beyond), so the CDN caches walls per message: a wall answers with
  `Cache-Control: public, s-maxage=86400, stale-while-revalidate=604800`,
  errors with `no-store`. A repeated message and every shared link cost no Jev
  call.
- **Presets never call Jev.** `scripts/build-presets.ts` writes
  `public/presets/<id>.json` from the fixture in wire shape before every build
  and dev session (`npm run presets`; `public/presets/` is generated and
  ignored). The fixture regained `latencyMs`, so a preset shows the latency of
  its recorded call. The builder refuses a fixture the code has drifted from,
  so a stale recording fails the build instead of shipping.
- **Abuse controls.** A Vercel firewall rule on the project, created through
  the REST API (`PATCH /v1/security/firewall/config`, `rules.insert`,
  `rule_judging_rate_limit_j015f9`): path equals `/api/react`, fixed window
  60 s, limit 60, keyed by IP, default 429 action. The handler answers 403 to
  a browser request whose `Sec-Fetch-Site` is neither `same-origin` nor
  `none`. The production Jev client does not retry 429 (`server/jev.ts` keeps
  the SDK's 408 and 5xx retries). Nothing typed is logged: statuses and
  durations only, and the Node adapter logs the path without the query.
- **Client cadence.** 600 ms debounce, one request in flight, the newest text
  queued behind it; the instant clear with abort stays. A 429 (Jev or
  firewall) is retried once after 2 s, then "The wall is busy right now. Try
  again in a few seconds."; other failures keep "Couldn't judge this message.
  Try again."
- **Share loop.** The URL carries the message (`/?m=`, `history.replaceState`);
  a page opened with `m` fills the box and judges through the cached GET.
  "Post on X" opens an intent with `A hundred faces read my post: {n}/100
  {reaction}, {u} understand it, {t} trust it. Show yours to the wall first:
  {url}` (`src/shared/share.ts`, tested). "Save the wall as an image" draws
  the header and the hundred faces onto a 1200×1200 canvas from the same
  geometry as the SVG wall (`src/client/image.ts`, `HEAD` and `faceGeometry`
  shared in `src/shared/face.ts`) and downloads `hundred-faces.png`. "Copy
  link" copies the URL. `public/og.png` (1200×630, the hot-take wall with the
  heading and tagline) is the card image; the `og:*` and `twitter:*` tags
  point at `https://hundred-faces.vercel.app`, hard-coded because the tags
  need absolute URLs and the host is only known at launch.
- **Copy, phone, dark.** The launch copy (tagline, intro, placeholder, "How it
  works", footer with the byline and source link). Ten columns fill any
  width (32 px faces on a 390 px phone), 44 px buttons on touch, the summary
  stacks. Without hover, a tap opens the person card as a bottom sheet; the
  same face or a tap elsewhere closes it; keyboard focus opens it everywhere.
  Every colour is a token on `:root`, redefined for `prefers-color-scheme:
  dark`. Vercel Web Analytics script tag (enabling it is a dashboard click).

## Decisions

- **Batch size 10** (was 5). The 2026-09-17 measurement already had the
  numbers: at 10, p50 latency 407 ms against 420 at 5, tokens 71.5k against
  74.7k, mean TV against batch size 1 0.148 against 0.115, top-reaction
  agreement 0.847 against 0.877, and the wall keeps its spread (mean pairwise
  TV 0.49 at both). Ten halves the calls per update, which doubles what the
  documented 1,200 requests a minute allows: 120 updates a minute across every
  visitor at ~74k input tokens (~$0.003) each. Below 5 the extra connections
  cost latency; above 10 the wall flattens.
- **GET with the message in the URL** buys the CDN cache. The cost: Vercel's
  own request logs record URLs, so the message text passes through platform
  logs even though the app logs none of it. The page's "Nothing you type is
  stored" is true of the app; it is not a claim about Vercel's log retention.
- **Presets from the recording**: same wire shape, same client path, no Jev.
  The latency a preset shows is the recorded call's, not the fetch of a static
  file.
- **Deployment protection stays on for previews.** Verification used a
  Protection Bypass for Automation secret (kept outside the repo); the bypass
  does not exempt the firewall rule, which the burst test relied on.
- **`engines.node` is `24.x`** so Vercel stops warning that `>=24` will
  auto-upgrade on the next major.

## Noticed, left alone

- The first `vercel` deploy of the newly created project was promoted to
  production by the CLI itself (no `--prod` was passed): `hundred-faces.vercel.app`
  serves that early build until the real production deploy overwrites it.
- With pauses under 600 ms between words the wall does not move mid-typing;
  the debounce is the decided one.
- 2,000 code points of non-Latin text URL-encode to more than Vercel's URL
  limit and would be refused by the platform before the handler's 413.
