# 2026-09-17: v1 built, measured, and verified

## What exists

A Vite page (vanilla TS) with a text box, five presets, a summary panel, and a
10x10 grid of SVG faces; a Node 24 server (built-in `http`, no framework) that
holds `TYPESAFE_API_KEY`, splits the hundred personas into batches of five, and
fires the twenty Jev calls in parallel; shared pure modules for questions,
blending, and aggregation; 28 offline tests against a recorded fixture of Jev's
real answers. Run commands are in `README.md`.

## Decisions

- **Batch size 5.** Measured against `jev-1.13.0` with the current wording
  (3 runs x 5 presets per size; agreement is against batch size 1, the cleanest
  state Jev can get; TV is total-variation distance between a persona's
  seven-way reaction distributions, 0 = identical, 1 = disjoint):

  | size | calls | latency p50 / p95 ms | tokens / update | mean TV vs size 1 | top agree | noul MAD |
  | ---: | ----: | -------------------: | --------------: | ----------------: | --------: | -------: |
  |   1  |  100  |   705-763 / 1213-1417 |        100,471 |                -  |        -  |       -  |
  |   2  |   50  |          635 / 1204  |         84,391 |             0.071 |     0.931 |    0.028 |
  |   3  |   34  |          593 /  802  |         79,245 |             0.095 |     0.899 |    0.035 |
  |   4  |   25  |          678 / 1015  |         76,351 |             0.105 |     0.892 |    0.038 |
  |   5  |   20  |          420 /  766  |         74,743 |             0.115 |     0.877 |    0.041 |
  |  10  |   10  |          407 /  676  |         71,527 |             0.148 |     0.847 |    0.047 |
  |  25  |    4  |          357 /  762  |         69,837 |             0.213 |     0.790 |    0.068 |
  |  50  |    2  |          548 /  852  |         69,274 |             0.300 |     0.749 |    0.100 |
  | 100  |    1  |  fails: `400 max_tokens_exceeded` (~98k tokens against the 64k context) |

  Run-to-run noise for the same size is TV 0.020-0.034, so the drift with
  batch size is real. Three things decided it: the drift is positional (at
  size 10 the first persona in a batch sits 0.08 from the baseline, the tenth
  0.13-0.21; at size 50 the last ones 0.30-0.69), sizes 5 and 10 keep the wall
  as varied as the baseline while 25 and 50 flatten it (mean pairwise TV
  between personas for the jargon blurb: 0.47 at 1, 0.49 at 5-10, 0.40 at 25,
  0.30 at 50), and batching leaks mass from "confused" into "neutral" (jargon
  confused: 44% alone, 30% at 5, 27% at 10, 11% at 50). Five is the smallest
  batch whose latency matches ten; below it the extra connections cost
  latency (25-100 calls: p50 590-760 ms). Trade-off accepted: 20 requests per
  update. In 1,500 requests fired 100 at a time (about 8,000 per minute in
  bursts) the API returned no 429 at all, so the documented 1,200/minute is
  not binding at demo load; the SDK retries 429 with backoff regardless and
  the page shows a rate-limit status if it ever gets through.
  Those numbers were taken with the earlier, shorter personas; the shipped
  personas are ~48 words each and cost ~77k tokens per update at size 5.

- **Compact question wording.** The first draft cost ~800 tokens per persona
  in questions; the compact draft costs ~570 with the same contrastive
  content. A/B on ten personas x two messages: mean TV 0.03-0.05 between
  wordings against 0.01-0.03 between two runs of the same wording; noul MAD
  0.02. Questions are 75% of every update's tokens, so this is the lever.

- **Stack.** Vanilla TS + Vite for the page, Node's `http` for the server
  (two routes and static files; a framework would save nothing), Node's
  built-in test runner (no dependency, runs the `.ts` files directly under
  type stripping; vitest would add a tree for no gain here). Dependencies:
  `@typesafe-ai/sdk` 0.6.0 (runtime); `vite` 8.3.0, `typescript` 7.0.2,
  `@types/node` 24 (dev). Nothing else.

- **Faces.** Seven parameters per reaction (mouth curve, mouth open, mouth
  skew, brow raise, brow inner tilt, brow skew, eye openness) plus an RGB tint,
  blended as a probability-weighted sum, tweened over 180 ms on update. Confused
  is the only asymmetric face (one brow up, mouth twisted), which makes it
  readable at 60 px next to annoyed.

- **Live loop.** 250 ms debounce, at most two requests in flight (a third
  keystroke burst is queued and sent when one returns), responses discarded
  by sequence number, the server aborts its Jev calls when the browser drops
  the connection. Message bound 4,000 characters (413 with the reason).

## Verified

- Real API probes (`npm run probe`, batch size 5):
  - Blunt -> gentle price increase: 55 faces more favourable, 0 less, 45
    within 0.1; 10 top reactions changed; annoyed 78% -> 67%, interested
    6% -> 15%; trust 11 -> 15 people; share 25 -> 19.
  - Spread, jargon blurb: mean pairwise TV 0.505; 53 annoyed, 34 confused, 9
    bored, 3 interested, 1 delighted. Most favourable Arjun Mehta (interested
    91%), Maya Goldberg, Henrik Dahl; least Rosa Delgado (confused 99%,
    understands 4%), Lucía Herrera (confused 100%, understands 2%), Emily Zhao.
    Understands: mean 16%, min 2%, max 66%. Clickbait: mean pairwise TV 0.381;
    81 annoyed; Susan Whitaker delighted 91% and would share 76%; Reginald
    Howard, Anika Sharma, Julien Moreau annoyed 99-100% and trust it 4-9%.
  - Self-consistency, same message three times: mean TV 0.020, p95 0.060, max
    0.120 (Mateo Rojas); 3 top-reaction flips in 200 transitions; noul move
    mean 0.010, max 0.070; aggregate counts 87/88/87, 12/11/10, 27/25/25.
  - Sanity: Lucía (no English) confused 100% and understands 2% on jargon and
    5% on plain; Bruce Kowalski understands jargon 6%, plain 36%; Henrik Dahl
    understands jargon 54%, plain 90%; Nigel Hartley annoyed 100% and trusts
    clickbait 6% while Gloria Nakamura trusts it 73%; Rosa Delgado still
    annoyed 94% at the gentle price rise (money worry), Marcus Lindqvist 75%.
  - Latency over 11 updates: p50 472 ms, p95 1,438 ms, min 377; ~77k input
    tokens per update. The measurement runs earlier saw p50 420 / p95 766 at
    this size; the API's latency varied across the evening.
- Real browser (Chrome 153 driven over the DevTools protocol, headless,
  scratch profile; the Claude-in-Chrome extension was not connected so
  Chrome control through it was unavailable): page loads with 100 faces
  resting; typing the clickbait headline word by word with 320 ms pauses
  produced 17 wall updates during the 11 s of typing, faces changing while
  later words were typed; every preset click moved 79-100 faces and settled
  in 418-917 ms; hovering all 100 faces per preset and recomputing the
  aggregates from the tooltip numbers matched the summary panel exactly
  (counts 85/15/21, 3/5/3, 81/17/4, 84/2/8; reaction mix within 0.5 points)
  once the status race below was fixed; a three-edit burst produced 25 calls
  and left the wall agreeing with a fresh direct call on 10/10 sampled faces;
  no console errors beyond Vite's missing favicon, since fixed with an inline
  one. Round trips seen by the browser: 347-1,247 ms over 27 calls.
- Production shape: `npm run build` then `NODE_ENV=production node
  server/main.ts` serves the page and assets with correct content types, a
  missing asset is a 404, and `/api/react` answers with 100 faces.
- `npm run check`: typecheck clean, 28 tests pass offline.

## Bugs the browser pass found and fixed

- An older in-flight response clearing "judging…" while a newer request was
  still out, so the summary panel could briefly show the previous message's
  aggregates next to the new faces (seen once: counts 85/3/9 shown against
  85/9/23 in the tooltips). Status now stays until the newest request lands.
- Found by inspection while chasing that race: clearing the box did not
  advance the shown sequence, so a response arriving after the clear would
  repopulate the wall. The clear now discards everything in flight. Verified
  with real keystrokes: clear while a request is in flight, the late response
  lands two seconds later, the wall stays resting and the summary blank; two
  overlapping requests settle with the status cleared only at the end.
- Not an app bug, but worth knowing for the next driver: over the DevTools
  protocol, Cmd+A needs `commands: ["selectAll"]` and Backspace needs
  `windowsVirtualKeyCode: 8`, or the box is never edited; and a Chrome window
  left occluded behind others pauses `requestAnimationFrame`, so the face
  tween never draws until a screenshot forces a frame. Headless avoids both
  the occlusion and the window on Mark's screen.

## Left out, and why

Per-face explanations, editing personas in the page, saving sessions, any
generative model: not in v1 by design. The measurement script keeps its raw
results outside the repo; only the summary above is recorded.
